ARRAYS, STRINGS, AND BASIC ALGORITHMS

Understanding arrays is foundational to computer science. Arrays provide O(1) random access to elements through direct indexing. When you declare an array of 100 integers, the operating system allocates a contiguous block of memory. To access element at index i, the CPU calculates address = base_address + (i * size_of_int). This calculation is O(1) regardless of which index you access.

Two-Pointer Technique for Sorted Arrays:
The two-pointer technique is invaluable for problems involving sorted arrays. The key insight is that if you start with one pointer at the beginning and one at the end, you can make intelligent moves based on the current sum or comparison.

For the classic Two Sum problem in a sorted array, start pointers at opposite ends. If the sum is too small, move the left pointer right (increasing sum). If too large, move right pointer left (decreasing sum). This runs in O(n) time with O(1) space, compared to O(n log n) with binary search or O(n^2) with brute force.

Three Sum extends this to find all unique triplets summing to zero. Sort first (O(n log n)), then for each element, use two-pointer technique on remaining array (O(n^2) total). Careful duplicate handling ensures unique results.

Container With Most Water demonstrates that sometimes the optimal pointer movement isn't obvious. Moving the taller wall inward can only decrease area since width shrinks and height is capped by the shorter wall. Only moving the shorter wall might increase area if the next element is taller.

Sliding Window for Substring Problems:
The sliding window technique maintains a window of elements and slides it through the string/array. This transforms many O(n^2) brute force problems into elegant O(n) solutions.

Longest Substring Without Repeating Characters uses a hash map to track character positions. As you expand the right pointer, if you encounter a repeated character still in the window, move the left pointer past its previous occurrence. The key insight is that this greedy approach works because we're looking for maximum length—skipping bad substrings can't make us miss the optimal answer.

Minimum Window Substring requires expanding the window to include all target characters, then contracting to find the minimum window. Track both what we need (character_count from target) and what we have (window_count). The formed counter tracks how many unique characters have sufficient count. This is trickier than it appears because we must find the optimal shrinking point.

Prefix Sums for Range Queries:
Prefix sums enable O(1) range sum queries after O(n) preprocessing. Build prefix[i] = sum of arr[0] to arr[i]. Then sum from i to j = prefix[j] - prefix[i-1].

The genius of subarray sum equals k is combining prefix sums with a hash map. If we're at position i with current_sum, and we've seen current_sum - k before at position j, then arr[j+1:i+1] sums to k. This works because (prefix[i] - prefix[j]) = k means the subarray between them sums to k. We track all previous prefix sums in a hash map for O(1) lookup.

2D prefix sums extend this: prefix[i][j] = arr[i][j] + prefix[i-1][j] + prefix[i][j-1] - prefix[i-1][j-1]. The subtraction prevents double-counting the overlapping rectangle.

Kadane's Algorithm for Maximum Subarray:
The breakthrough insight is that at each position, you have a choice: extend the previous subarray or start fresh. If the previous sum is negative, starting fresh is better. This greedy decision, made at each step, produces the optimal result.

The algorithm tracks max_ending_here (maximum sum subarray ending at current position) and max_so_far (best answer seen). Surprisingly simple but profound—it solves a problem that seems to require O(n^2) checking all subarrays in just O(n) time.

Maximum Product Subarray requires tracking both maximum and minimum because a negative number can turn a small minimum into a large maximum. When multiplying by negative numbers, the min value becomes relevant.

HASH MAPS: EFFICIENT LOOKUPS AND GROUPING

Hash maps provide O(1) average-case lookup, insert, and delete by mapping keys to array indices. The hash function distributes keys across an array, and collisions are handled via chaining (linked lists at each slot) or open addressing (finding alternate slots).

Load factor determines when to rehash. When load_factor = num_elements / array_size exceeds threshold (typically 0.75), the hash map allocates a new larger array, rehashes all elements, and deallocates the old one. Though rehashing is O(n), it happens infrequently enough that amortized cost per insertion remains O(1).

Two Sum Problem demonstrates hash map power. Instead of checking all pairs (O(n^2)), store seen numbers in a hash map. For each number, check if complement is already seen. One pass achieves O(n) time and O(n) space.

Frequency Counting and Grouping Anagrams show how hash maps group related elements. For anagrams, use sorted word as key—all anagrams sort to the same key. This elegantly groups related strings.

LRU Cache combines hash map with doubly linked list. Hash map provides O(1) lookups, doubly linked list maintains access order. When cache reaches capacity, remove least recently used (tail of list). When accessed, move to head (most recently used). Both operations are O(1).

LINKED LISTS: DYNAMIC SEQUENTIAL STORAGE

Linked lists store elements dynamically without requiring contiguous memory. Each node contains data and a reference to the next node (and previous node in doubly linked lists).

Floyd's Cycle Detection uses two pointers moving at different speeds. Slow pointer moves 1 step, fast pointer moves 2 steps. If a cycle exists, they eventually meet. If no cycle, fast pointer reaches end. Time: O(n), Space: O(1)—much better than hash set approach using O(n) space.

To find cycle start after detecting it: reset slow pointer to head, advance both one step at a time. They meet at cycle start. The mathematics: if distance from head to cycle start is d, they meet at that point because slow traveled d+x (x steps into cycle) while fast traveled d+x+2*(x) = d+3x, and slow is now at d again which means fast is at d+2x into cycle, continuing this logic they meet at cycle start.

Merging Sorted Lists compares head nodes of two lists and appends the smaller one. Create dummy node to simplify code. Time: O(n+m), Space: O(1) for merging.

Reversing Linked List uses three pointers (prev, current, next) to reverse links. Iterative approach is preferred over recursive to avoid stack overflow on large lists.

STACKS AND QUEUES: ORDER-CONSTRAINED ACCESS

Stacks (LIFO) and Queues (FIFO) are fundamental abstract data types. Stacks can be implemented with arrays (last element is top) or linked lists. Same for queues.

Monotonic Stack solves next greater element: maintain stack in decreasing order. When new element arrives, pop all smaller elements (they found their next greater), then push current element. This gives O(n) solution compared to O(n^2) brute force.

Balanced Parentheses uses stack to track opening brackets. When closing bracket found, check if it matches top of stack. This ensures proper nesting.

Largest Rectangle in Histogram uses monotonic stack to track heights. When encountering a height drop, calculate rectangles for all dropped bars. The width extends to where we are now.

Priority Queues (heaps) are complete binary trees maintaining heap property. Min-heap: parent <= children. Max-heap: parent >= children. Insertion and extraction are O(log n).

Building a heap from array is O(n) using Floyd's algorithm (heapify from bottom-up), better than inserting elements one by one which is O(n log n).

BINARY TREES AND TRAVERSALS

Tree traversals visit nodes in different orders for different purposes:

Inorder (left-root-right) yields sorted output for BST. Used to verify BST property or get sorted elements.

Preorder (root-left-right) is used for tree serialization and cloning. Process root first enables reconstruction.

Postorder (left-right-root) is used for tree deletion (delete children before parent) and expression evaluation.

Level-order (BFS with queue) explores layer by layer. Used for finding shortest path in unweighted trees and serialization.

Binary Search Trees maintain ordering: left subtree < root < right subtree. Average case is O(log n) for search/insert/delete but degenerates to O(n) for sorted input (becomes linked list).

Balancing techniques:
- AVL: strictly balanced, height difference <= 1, requires rotations after every insert/delete
- Red-Black: less strict balance, black node property maintains approximate balance with fewer rotations
- Both provide O(log n) guarantees

Tries (Prefix Trees) store strings efficiently with character nodes. All operations (insert, search, startsWith) are O(L) where L is string length. Applications: autocomplete, spell checking, IP routing.

GRAPH FUNDAMENTALS AND TRAVERSAL

Graphs represent networks of connected nodes. Two representations:
- Adjacency list: space-efficient for sparse graphs, natural for traversals
- Adjacency matrix: O(1) edge lookup, better for dense graphs

BFS (Breadth-First Search) explores layer by layer using a queue. Applications:
- Shortest path in unweighted graphs: each edge is unit cost
- Level-order traversal: process nodes by distance from source
- Bipartite checking: color nodes with two colors, BFS ensures valid coloring
- Word ladder: find minimum transformations (BFS finds shortest path)

DFS (Depth-First Search) explores deeply using recursion or stack. Applications:
- Cycle detection: back edge indicates cycle
- Topological sort: post-order processing gives reverse topological order
- Strongly connected components: Tarjan's algorithm uses DFS with stack
- Island counting: explore each island completely

Dijkstra's Algorithm finds shortest paths with non-negative weights. Use min-heap to always expand node with smallest distance. Time: O((V+E) log V). Fails with negative weights because greedy choice might not be globally optimal.

Bellman-Ford handles negative weights and detects negative cycles. Relax all edges V-1 times. If any edge still relaxes on V-th iteration, negative cycle exists. Time: O(VE), much slower than Dijkstra but handles negative weights.

Floyd-Warshall finds all-pairs shortest paths. dp[i][j][k] = shortest path from i to j using only nodes 0..k as intermediates. Time: O(V^3), useful for small graphs or when all-pairs are needed.

Union-Find (Disjoint Set Union) tracks connectivity efficiently. Path compression and union by rank combine to achieve nearly O(1) amortized performance (specifically O(α(n)) where α is inverse Ackermann function).

Applications:
- Kruskal's MST: sort edges, union endpoints if not already connected
- Cycle detection in undirected graphs: if union returns false, cycle found
- Connected components: union all connected pairs, then count unique parents

DYNAMIC PROGRAMMING: OPTIMAL SUBSTRUCTURE

DP solves problems with optimal substructure and overlapping subproblems by caching results.

Top-down (Memoization): recursive with cache. Natural problem decomposition. Risk: stack overflow for deep recursion.

Bottom-up (Tabulation): iterative, fills table from small to large. More explicit about dependencies. Better for large problems.

0/1 Knapsack: dp[i][w] = max value using first i items with weight limit w. Recurrence: take or don't take item i. Process weights backward to avoid using same item twice. Time: O(nW), Space: O(nW) optimizable to O(W).

Unbounded Knapsack: items reusable, process weights forward instead of backward. Applications: coin change (minimum coins), integer break (maximum product).

Longest Common Subsequence: dp[i][j] = LCS length of s1[0:i] and s2[0:j]. If characters match, extend previous LCS. Otherwise take maximum from excluding current character in either string. Time: O(mn).

Longest Increasing Subsequence: O(n^2) DP solution straightforward. O(n log n) solution uses binary search on tails array—tails[i] = smallest tail value of all LIS of length i+1. Patience sorting principle.

Edit Distance: minimum operations (insert, delete, substitute) to transform s1 to s2. dp[i][j] = distance between s1[0:i] and s2[0:j]. Time: O(mn).

Matrix Chain Multiplication: optimal parenthesization minimizes scalar multiplications. Interval DP: dp[i][j] = minimum cost to multiply matrices i through j. Time: O(n^3).

Palindromic Substrings: expand around center for O(n^2). Manacher's algorithm achieves O(n) using symmetry properties but is complex.

State Compression DP: bitmask represents subset of elements. TSP: dp[mask][i] = minimum cost tour visiting cities in mask ending at i. Time: O(2^n * n^2), feasible for n <= 20.

Tree DP: compute answers at each node using children's answers. Tree diameter: max(left height + right height) across all nodes. Maximum path sum: max(node.val + max_left_path + max_right_path).

SECTION 3: SYSTEM DESIGN FUNDAMENTALS

SCALABILITY AND LOAD DISTRIBUTION

Vertical scaling (scale-up) adds resources to single machine. Limited by hardware ceiling, expensive, simpler architecturally.

Horizontal scaling (scale-out) distributes across multiple machines. Theoretically unlimited, cost-effective, introduces complexity.

Stateless services scale horizontally naturally—any server can handle any request. Stateful services require session affinity or distributed state storage.

Load balancing distributes incoming traffic:
- Round-robin: simple, equal distribution, ignores load
- Least connections: routes to server with fewest connections, better for unequal loads
- IP hash: same client always hits same server, useful for session affinity
- Consistent hashing: minimal redistribution when servers added/removed

Layer 4 (TCP/UDP) vs Layer 7 (HTTP) load balancing:
- Layer 4: fast, non-HTTP protocols, no content inspection
- Layer 7: can route by URL path, hostname, headers, cookies, enables A/B testing

CACHING STRATEGIES

Cache-aside (lazy loading): application reads from cache, on miss fetches from database and populates cache. Simple, only useful data cached, cache misses hit database. Risk: stale data.

Write-through: write to cache and database synchronously. Strong consistency, higher write latency. Both must succeed.

Write-behind (write-back): write to cache only, asynchronously flush to database. Fast writes, throughput optimized. Risk: data loss if cache crashes before flush.

Cache eviction when capacity reached:
- LRU (Least Recently Used): good for temporal locality
- LFU (Least Frequently Used): good for frequency patterns
- FIFO: simple, ignores patterns
- TTL (Time-To-Live): automatic expiration

Thundering herd problem: popular key expires, all requests miss cache, overload database. Solutions:
- Probabilistic early expiration: refresh before TTL expires
- Request coalescing: first request fetches, others wait for result
- Circuit breaker: fail fast if database overwhelmed

CDN (Content Delivery Network) distributes static content from edge nodes geographically close to users.
- Push CDN: pre-upload content, guaranteed availability
- Pull CDN: fetch from origin on miss, cache at edge

Reduces latency from ~300ms (transatlantic) to ~10ms (local cache). Origin load reduced dramatically.

DATABASES: RELATIONAL VS NOSQL

Relational databases (PostgreSQL, MySQL) enforce ACID transactions. Indexes (B-tree for range, hash for equality) accelerate queries. Write-Ahead Log ensures durability. MVCC enables readers not to block writers.

Database sharding partitions data horizontally:
- Range sharding: partition by key range, simple but prone to hotspots
- Hash sharding: hash function determines shard, even distribution, harder to reason about
- Directory sharding: external mapping from key to shard, flexible but adds lookup

Cross-shard queries are expensive. Relatedness matters—keep related data on same shard.

Replication for read scaling and failover:
- Primary-replica: primary accepts writes, replicas serve reads
- Synchronous replication: writes must replicate before confirming, strong consistency, higher latency
- Asynchronous replication: write confirms immediately, replicates in background, better throughput, risk of loss
- Multi-master: multiple writers, requires conflict resolution (last-write-wins, custom logic, CRDTs)

NoSQL databases chosen for different reasons:
- Document stores (MongoDB): flexible schema, nested data
- Wide-column (Cassandra): write-optimized, time-series data, tunable consistency
- Key-value (Redis): O(1) lookups, perfect for caching
- Graph (Neo4j): native graph queries, relationship-heavy data
- Search (Elasticsearch): inverted indexes, full-text search

CAP Theorem: distributed system can have at most two of Consistency, Availability, Partition-tolerance. Partition tolerance is mandatory in distributed systems (network failures happen). Choose between consistency and availability.
- CP systems: HBase, Zookeeper, MongoDB (w:majority)
- AP systems: Cassandra, CouchDB, DynamoDB (eventually consistent)

MESSAGE QUEUES AND EVENT STREAMING

Message queues decouple producers from consumers. Producers append messages, consumers read asynchronously. Enables load buffering, temporal decoupling, scaling independent components.

RabbitMQ (AMQP protocol):
- Exchanges route messages to queues via bindings
- Direct exchange: message goes to queue with matching routing key
- Topic exchange: routing key patterns (e.g., logs.warning.*)
- Fanout exchange: broadcast to all bound queues
- Durable queues persist to disk
- At-least-once delivery: messages retried if not acknowledged

Amazon SQS:
- Managed service, no infrastructure to manage
- Standard queues: unordered, at-least-once
- FIFO queues: ordered, exactly-once, lower throughput
- Messages can be processed by multiple consumers (polling model)

Apache Kafka:
- Distributed event log platform, not traditional queue
- Topics partitioned, each partition is ordered immutable log
- Producers append to partition (determined by key or round-robin)
- Consumers track offset independently, enabling replay
- Consumer groups: multiple consumers divide partitions
- Retention-based: messages retained for configurable period, not removed after consumption
- Scales to millions of messages/second
- Used for: real-time analytics, data pipeline, change data capture

Guarantees:
- At-most-once: fire and forget, message may be lost
- At-least-once: retry until acknowledged, message may be duplicated
- Exactly-once: hardest to achieve, requires idempotent processing and deduplication

MICROSERVICES ARCHITECTURE

Decompose monolith into small, independently deployable services. Each service owns its data, no shared database.

Benefits:
- Independent scaling: only scale services under load
- Fault isolation: service failure doesn't crash others
- Technology heterogeneity: different services use best tools
- Faster deployment: deploy single service, not entire app

Challenges:
- Distributed system complexity: network calls fail, latency exists
- Data consistency: distributed transactions hard
- Service discovery: services appear/disappear
- Monitoring: harder to track issues across services

Communication patterns:
- Synchronous (REST/gRPC): request-response, blocking, tightly coupled
- Asynchronous (Kafka/RabbitMQ): events, decoupled, enables buffering

Service discovery: services register with registry (Consul, Eureka), clients look up dynamically. Enables adding/removing services without configuration changes.

Circuit breaker pattern: wrap calls to external services. Track failure rate in rolling window. When exceeds threshold, "open" circuit—fail fast without calling service. Half-open state periodically tests recovery.

API Gateway: single entry point for clients. Handles:
- Authentication: verify client identity
- Rate limiting: prevent abuse
- SSL termination: encrypt client connection
- Request routing: route to appropriate service
- Response transformation: adapt format for client

GOOGLE'S INFRASTRUCTURE

Google File System (GFS) / Colossus:
- Distributed file system storing petabytes across thousands of servers

MapReduce:
- Parallel programming model for processing massive datasets
- Map phase: each worker processes input split, emits (key, value) pairs
- Shuffle phase: sort and group by key, redistribute to reducers
- Reduce phase: each reducer aggregates values for a key
- Fault tolerant: failed task retried on different machine
- Used for: web indexing (page analysis), log processing, inverted indices
- Replaced by Flume (streaming) and Dataflow (unified streaming + batch)

Bigtable:
- Distributed NoSQL database
- Row key sorted lexicographically—range scans are efficient
- Column families: groups of columns, sparse storage
- Tablets: partitions of row key space, served by tablet servers
- High throughput: millions of writes/second
- Used for: search index, Gmail metadata, Maps

Google Spanner:
- Globally distributed relational database with external consistency
- TrueTime API: GPS + atomic clocks provide synchronized timestamps
- Enables ACID transactions across datacenters with strong consistency
- Sharding via Paxos replication groups
- Used for: ads system, finance

PageRank:
- Assigns importance to web pages
- PageRank(page) = sum over incoming pages of (PageRank(page_i) / out_links(page_i))
- Iterative algorithm until convergence
- Damping factor (0.85): models random web surfer
- Computed efficiently with MapReduce
- Foundational to Google Search ranking

Consistent Hashing:
- Maps both servers and keys to a ring (hash space)
- Each key assigned to nearest server clockwise
- Adding/removing server redistributes only O(K/N) keys
- Virtual nodes: multiple points per server for better distribution
- Enables incremental scaling without rehashing all data
- Used in: DynamoDB, Cassandra, Redis Cluster, CDNs

SEGMENT TREES: EFFICIENT RANGE QUERIES

Segment trees answer range queries (sum, min, max in range) in O(log n) time with O(n) space.

Structure: complete binary tree where each leaf is array element, internal node represents aggregate of children.

Construction: bottom-up approach builds tree in O(n) time.

Range query: decompose query into logarithmic number of tree nodes, answer from combining node values.

Point update: modify element, propagate changes up tree to root. O(log n).

Example: array [1, 3, 5, 7, 9]. Query sum[1, 3] (elements 3, 5, 7). Segment tree answers in O(log n).

Lazy propagation: defer updates until needed. Mark range as "modified", push changes down tree only when queried. Enables range updates in O(log n).

FENWICK TREE (BINARY INDEXED TREE)

Simpler alternative to segment trees for prefix sum queries. Space O(n), queries O(log n), updates O(log n).

Key insight: bit manipulation encodes parent-child relationships. If current index has bit i set, parent removes bit i, adds bit i-1.

Prefix sum query at index i: sum bits from index i to 0 by repeatedly removing lowest set bit.

Range sum: prefix_sum[j] - prefix_sum[i-1].

Elegantly simple with minimal space and excellent cache locality.

B-TREES: EFFICIENT DISK-BASED SEARCH

B-trees maintain sorted order with logarithmic access time while minimizing disk I/O.

Motivation: in-memory trees do random access per node. Disk I/O extremely expensive (milliseconds vs nanoseconds). Minimize number of disk accesses.

B-tree degree: each node contains many keys and children. Degree t: each node has t-1 to 2t-1 keys, t to 2t children.

Search: similar to binary search but at each node, multiple branches possible.

Insertion: insert in leaf. If leaf full, split into two nodes, promote middle key to parent.

Deletion: remove from node. If node too small after removal, merge with sibling.

B-trees guarantee: tree height O(log n) with branching factor many times larger than binary trees. Reduces disk I/O dramatically.

Applications: databases, filesystems (NTFS, ext4).

SECTION 9: PRACTICAL PROBLEM-SOLVING PATTERNS
========================================================================

SLIDING WINDOW ADVANCED PATTERNS

Fixed window size: maintain window of K elements, slide right. Example: maximum sum of K consecutive elements.

Shrinking window: expand right while condition not met, shrink left when met. Example: minimum window substring containing all characters.

Two-pointer variant: instead of sliding, move pointers independently. Useful when constraint involves two pointers. Example: container with most water.

BACKTRACKING AND COMBINATORIAL PROBLEMS

Backtracking explores solution space by trying each possibility and undoing if not viable. Essential for:
- Permutations: generate all orderings
- Combinations: generate all subsets of size K
- N-Queens: place N queens on board
- Sudoku solver: fill puzzle respecting constraints

Pattern:
```
function backtrack(solution, choices):
  if solution is complete:
    return solution
  for choice in choices:
    if choice is valid:
      add choice to solution
      result = backtrack(solution, remaining_choices)
      if result found:
        return result
      remove choice from solution
  return null
```

Pruning: eliminate branches that can't possibly lead to solution. Dramatically reduce search space.

Memoization: cache results to avoid recomputing subproblems.

GREEDY ALGORITHMS

Greedy makes locally optimal choice at each step, hoping for global optimum. Doesn't always work but very efficient when applicable.

Works for: interval scheduling (select non-overlapping intervals), activity selection, Huffman coding, Kruskal's MST.

Proof strategy: exchange argument. Show that if greedy solution differs from optimal, you can exchange one step to match optimal without worsening solution. Repeat until they match.

DIVIDE AND CONQUER

Divide problem into independent subproblems, solve recursively, combine results.

Examples:
- Merge sort: divide array, sort halves, merge
- Quick sort: partition around pivot, sort partitions
- Binary search: search left or right half
- Closest pair of points: divide plane, find closest pair in each half, handle boundary

CONSENSUS ALGORITHMS

Consensus: multiple nodes must agree on value despite failures.

Paxos: fundamental consensus algorithm
- Nodes may fail (but don't exceed majority)
- Messages may be lost or reordered
- Guarantees: all non-failed nodes eventually agree
- Used in: Chubby (Google's distributed lock service)

Raft: newer, simpler consensus algorithm
- Similar guarantees to Paxos
- Easier to understand and implement
- Used in: etcd, Consul, many modern systems

Process:
1. Candidate nodes propose value
2. Quorum (majority) must accept
3. Once majority accepts, value committed
4. Non-faulty nodes eventually learn committed value

Byzantine Fault Tolerance:
- Handles malicious nodes (not just failed)
- Requires 2/3 honest nodes
- Higher overhead than Crash Fault Tolerance
- Used in: blockchain, high-security systems

SECTION 11: OPTIMIZATION TECHNIQUES FOR INTERVIEWS
=========================================================================

TIME COMPLEXITY OPTIMIZATION

Linear → sublinear:
- Use data structures: hashtable O(1) lookup vs array O(n) scan
- Binary search: O(log n) for sorted data
- Indexing: database index makes search fast

Quadratic → linear:
- Hash maps for lookups: instead of nested loop searching, use hash
- Two pointers: traverse from ends, meet in middle
- Monotonic structures: maintain ordering to skip redundant checks

Polynomial → logarithmic:
- Divide and conquer: break problem into pieces
- Binary lifting: precompute powers for fast range queries
- Segment trees: answer range queries in O(log n)

SPACE OPTIMIZATION

Trade space for time: preprocessed data enables faster queries.

Compress data: instead of storing full data, store compressed representation. Hash values, bit operations.

In-place modifications: reuse input space for output. Careful bookkeeping required.

Streaming: process data as it arrives without storing all. Impossible for some problems, revolutionary for others.

EDGE CASE HANDLING

Empty input: algorithm should handle empty arrays, strings, graphs, etc.

Single element: often edge case, separate logic if needed.

Duplicates: algorithm behavior with repeated elements

Negative numbers: handle negative values, overflow possibilities

Very large numbers: consider overflow, modular arithmetic

Order dependence: results should be consistent regardless of input order (unless order matters)

Special characters: handle all ASCII or Unicode characters

Boundary values: test min/max values of data types

SECTION 13: SPECIFIC ALGORITHM PATTERNS
=========================================================================

GRAPH PATTERNS

Connected components:
- DFS/BFS to find groups
- Union-Find for efficient tracking
- Applications: islands, network connectivity, social graph analysis

Shortest path:
- Unweighted: BFS
- Weighted non-negative: Dijkstra
- Weighted with negatives: Bellman-Ford
- All-pairs: Floyd-Warshall

Topological sort:
- Use DFS post-order or Kahn's algorithm
- DAG only (no cycles)
- Applications: task scheduling, dependency resolution

Bipartite checking:
- Use 2-coloring via BFS/DFS
- Detect odd cycles (only exist in non-bipartite)
- Applications: matching problems, graph coloring

TREE PATTERNS

Tree DP:
- Solve for subtree, combine for parent
- Root causes of typical patterns
- Applications: tree diameter, path sums, counting

LCA (Lowest Common Ancestor):
- Binary lifting: precompute ancestors, query in O(log n)
- LCA at depth k: follow parent pointers O(log n) times
- Applications: distance queries, relationship detection

Heavy-light decomposition:
- Decompose tree into paths
- Answer queries on paths efficiently
- Advanced pattern for competitive programming

STRING PATTERNS

KMP (Knuth-Morris-Pratt):
- Find substring in O(n+m) (linear time)
- Failure function encodes pattern self-overlaps
- Applications: pattern matching, string searching

Z-algorithm:
- Compute Z[i] = length of prefix matching at position i
- Linear time string matching
- More intuitive than KMP in some cases

Rolling hash (Rabin-Karp):
- Compute hash of substrings
- Collision risk requires care but very practical
- Applications: substring search, plagiarism detection

Suffix array:
- Sort all suffixes of string
- Enables efficient pattern matching
- Advanced but powerful data structure

MATHEMATICAL PATTERNS

Modular arithmetic:
- Computing (a*b) % m carefully to avoid overflow
- Modular inverse for division
- Fermat's Little Theorem: a^(p-1) ≡ 1 (mod p) for prime p
- Applications: cryptography, competitive programming

Prime checking:
- Trial division up to sqrt(n)
- Miller-Rabin for large numbers (probabilistic)
- Sieve of Eratosthenes for multiple primes

Combinatorics:
- Factorials, combinations C(n,k), permutations
- Pascal's triangle for efficient computation
- Inclusion-exclusion principle
